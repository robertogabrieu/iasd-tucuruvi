# Eventos — plano de implementação

> **Para quem executa:** este plano é feito para execução delegada (skill `orquestrador`). O agente
> principal decide, versiona e escreve os arquivos de dono compartilhado; cada pacote vai para um
> `implementador`. Os passos marcados com `- [ ]` são o rastreamento.

**Objetivo:** publicar um evento da igreja por um formulário no painel e receber um link com página
própria, capa montada a partir da foto do responsável (com o fundo removido no navegador) ou da
arte que a pessoa já tem.

**Arquitetura:** módulo `eventos` no backend em camadas, espelhando o de boletins; tabela com
colunas fixas; recorte de fundo no navegador de quem publica; imagens de compartilhamento geradas
no servidor com `sharp`; página pública de layout fixo compartilhada com a pré-visualização.

**Stack:** Express 5 · PostgreSQL 16 · React 18 + Vite · Tailwind · Zod · sharp · TipTap ·
Transformers.js (novo).

**Spec:** `docs/superpowers/specs/2026-08-29-eventos-design.md`
**Mockup (alvo visual):** `docs/superpowers/specs/2026-08-29-eventos-mockup.html`
**História:** `docs/historias/US-29-eventos.md` · **Issue:** #19

## Restrições globais

Valem para todos os pacotes; nenhum briefing precisa repeti-las, mas todos as respeitam.

- **Arquitetura em camadas obrigatória:** `routes → controller → service → repository → db`. O
  controller não executa SQL; o service não toca `req`/`res`; o repository não tem regra de negócio.
- **ESM no backend:** imports internos em `server/` levam sufixo `.js` mesmo em arquivos `.ts`.
  Sem isso o build quebra em runtime.
- **Kit de UI obrigatório:** toda tela do painel compõe `@/painel/ui`. Faltou primitivo? **Adiciona
  ao kit** e documenta em `docs/patterns/area-administrativa-visual.md` — nunca improvisa na tela.
- **Sem dependência nova de UI.** Nada de shadcn, Radix, biblioteca de data ou de ícones.
- **Paginação:** `?page=&limit=` com envelope `{ data, pagination }`, via `server/core/pagination.ts`.
- **Cores só pelos tokens `iasd-*`;** verde/vermelho/âmbar só para feedback. Sem tema escuro.
- **Do mockup se copia estrutura e decisão, nunca CSS.** As classes saem dos componentes do kit.
  **Divergiu do que está escrito aqui? O mockup vence.**
- **Nomes fechados:** permissões `evento:write` e `evento:publish`; tabela `eventos`; módulo
  `server/modules/eventos/`.
- **Nenhum subagente roda `git`.** Quem versiona é o principal.

## Sobre testes neste projeto

O projeto **não tem suíte ativa** — três arquivos em `__tests__/`, todos de função pura, e nenhum
script `test` no `package.json`. Este plano não muda isso: escreve teste **só onde a lógica é pura
e o teste é barato** (geração de slug, regras de validação, montagem do `.ics`), no mesmo formato
dos que já existem, e verifica o resto **no navegador**, que é o método declarado do projeto.

O pacote 1 acrescenta `"test": "jest"` ao `package.json` para os checkpoints serem um comando só.
